# diff-review

Guided review по образцу plannotator. Ты, основная сессия, определяешь, что ревьюить, и собираешь дифф. Гайд пишет субагент. Ты валидируешь результат, поднимаешь локальную страницу и обрабатываешь фидбек пользователя.

Аргументы: `$ARGUMENTS`

Скрипты лежат в `${CLAUDE_SKILL_DIR}/scripts/`, у каждого есть `--help`. Сам дифф не читай: он нужен субагенту, а не тебе.

## 1. Определи цель

Цель — это **репозиторий** (каталог, часто worktree) плюс **режим** для `collect.py`.

Токены аргумента, в любом порядке:

| Токен | Что делать |
|---|---|
| путь к каталогу | `--repo <путь>` |
| `uncommitted` | `--mode uncommitted`: HEAD против рабочего дерева, включая untracked |
| `staged` | `--mode staged`: только индекс |
| `<sha>` | `--mode commit --ref <sha>` |
| `<A>..<B>`, `<A>...<B>` | `--mode range --ref <A>..<B>` |
| имя ветки | `--mode branch --ref <ветка>`: от merge-base с базой до ветки |
| `--base <ref>` | передать как есть |
| ничего из этого | режим по умолчанию `since-base`: от merge-base с базовой веткой до рабочего дерева, включая untracked |

Ветку от sha отличай через `git -C <repo> rev-parse --verify`. Свободный текст («worktree с фиксом логина») сопоставь с контекстом сессии по правилам ниже.

**Если репозиторий не указан**, выведи его из этой сессии, по приоритету:
1. Где делалось обсуждаемое изменение: пути из Edit и Write, `EnterWorktree`, `git worktree add`, `cd` в Bash-командах. Корень: `git -C <каталог> rev-parse --show-toplevel`. Сессия могла начаться в основной ветке, а правки шли в worktree. Тогда цель — worktree.
2. Ветка, которую создавали или обсуждали. Её worktree можно найти через `git -C <repo> worktree list`.
3. Иначе репозиторий текущего каталога.

Если подходят несколько кандидатов и выбор не очевиден, спроси через AskUserQuestion со списком. Не угадывай.

## 2. Собери дифф

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/collect.py --repo <repo> [--mode <режим>] [--ref <ref>] [--base <ref>]
```

Скрипт пишет `guide.patch` и `meta.json` в новый каталог `$TMPDIR/diff-review/...` и печатает JSON-сводку с `outdir`. Индекс пользователя не трогает.
- Код 3 — изменений нет. Скажи об этом одной строкой и остановись.
- Код 2 — ошибка, текст в stderr. Покажи её пользователю.
- Если в сводке есть `notes` (например, базовая ветка не найдена), передай их пользователю.

Перед запуском субагента одна строка пользователю: «Ревьюю `<root>`, `<label>`: N файлов (+a −d). Гайд пишет субагент.»

## 3. Запусти субагента

Вызови Agent с параметрами `subagent_type: "general-purpose"`, `model: "sonnet"`, `effort: "medium"`, `description: "Guided review: <repoName>"`. Промпт ниже, подставь значения:

```
Напиши guided review на русском для набора изменений.

Методология и формат — прочитай первым: ${CLAUDE_SKILL_DIR}/references/guide-method.md
Дифф: <outdir>/guide.patch
Метаданные и авторитетный список файлов: <outdir>/meta.json
Репозиторий (только для точечных справок): <root>
Результат запиши в: <outdir>/guide.json

Контекст от автора изменения: <1–3 предложения о том, зачем делалось изменение, из этой сессии; если не обсуждалось — «нет»>

Правила:
- Ничего не меняй в репозитории: не редактируй файлы, не коммить, не трогай индекс. Писать можно только в <outdir>.
- Перед завершением запусти проверку и исправляй guide.json, пока она не пройдёт:
  python3 ${CLAUDE_SKILL_DIR}/scripts/validate.py --guide <outdir>/guide.json --meta <outdir>/meta.json
- Ответь одной строкой: число глав и вывод валидатора.
```

Дождись уведомления о завершении. Не пиши гайд сам и не читай дифф, пока субагент работает.

## 4. Проверь

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/validate.py --guide <outdir>/guide.json --meta <outdir>/meta.json
```

Не прошло — один раз отправь вывод валидатора тому же субагенту через SendMessage с просьбой исправить. Снова не прошло — покажи пользователю ошибки и путь к `outdir` и остановись.

## 5. Открой страницу

Запусти в фоне, Bash с `run_in_background: true`:

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/serve.py --dir <outdir> --open
```

Первая строка вывода — `DIFF_REVIEW_URL: <url>`. Сообщи пользователю URL и что сессия свободна, пока он читает. Сервер ждёт до 3 часов.

На странице два режима: «Гайд» (открывается первым) и «Файлы» с деревом файлов. В обоих можно раскрыть контекст между ханками и открыть файл целиком: `collect.py` кладёт полный текст изменённых файлов в `full.patch`.

## 6. Обработай решение

Когда фоновая команда завершится, последняя строка вывода будет такой:

```
DIFF_REVIEW_RESULT: feedback|approved|closed|timeout [<путь к feedback.md>]
```

- `feedback` — прочитай `feedback.md` и отнесись к нему как к сообщению пользователя. Это его ревью твоих или чужих изменений в репозитории `<root>`. На вопросы ответь. Просьбы о правках выполни в `<root>`, то есть в том worktree, который ревьюился, а не в каталоге сессии. Неоднозначное уточни. Потом предложи перезапустить `/diff-review`, чтобы проверить результат.
- `approved` — подтверди одной строкой. Если приложен `feedback.md`, прочитай и учти комментарии. Ничего не коммить без отдельной просьбы.
- `closed` или `timeout` — сообщи одной строкой, что ревью закрыто без ответа.
